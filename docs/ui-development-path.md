# 小程序页面与功能完善路径

## 1. 背景与目标

当前微信开发者工具运行的是 Taro 正式工程：

- `apps/teacher-miniapp`
- `apps/parent-miniapp`

浏览器中曾直接打开的页面来自历史静态原型：

- `archive/apps/teacher-app`
- `archive/apps/parent-app`

两套页面不是同一套组件和样式。历史原型展示了较完整的品牌视觉和交互设想，正式小程序则优先完成了真实 API 闭环，因此目前存在视觉差异、占位页面和已存在接口尚未接入前端的问题。

本路径的目标是在继续生产登录和部署前，把正式小程序完善到可以交给老师、家长持续试用的状态。

## 2. 开发原则

1. 历史原型作为视觉与信息架构参考，不直接复制原型中的假数据和仅弹提示的按钮。
2. 正式 Taro 小程序是唯一交付工程，新增页面和功能都写入 `apps/*-miniapp`。
3. 优先接入已经存在的真实 API，再新增确有必要的数据表和接口。
4. 每个按钮必须满足以下一种结果：完成真实操作、进入真实页面、明确显示尚不可用；不保留无响应按钮。
5. 教师端和家长端使用统一品牌色、卡片、状态标签、加载态、空状态和错误态。
6. 每一批修改都需要在微信开发者工具中人工验收，不能只以浏览器原型或构建通过作为完成依据。

## 4. 推荐开发批次

### UI-01 双端首页与视觉基线

状态：开发中，代码已实现，等待微信开发者工具人工验收。

范围：

- 教师端工作台：问候卡、实时统计、快捷入口、今日待办、负责班级。
- 家长端首页：孩子卡片、多孩子切换、快捷入口、今日提醒、成长预览。
- 建立绿色品牌色、卡片、圆角、阴影、状态标签和内容层级基线。
- 快捷入口必须连接现有流程、作业、成长、通知和沟通页面。

验收：

- 微信开发者工具中的信息层级与历史原型方向一致。
- 教师、家长首页都使用真实 API 数据，不展示固定业务数量。
- 四个快捷入口均可到达对应真实页面。
- 加载失败、无孩子、无班级和无记录时有明确状态。

### UI-02 教师教学中心补齐

状态：已完成，并通过微信开发者工具人工验收。

范围：

- 将教师“教学”页面拆分为“教学记录”和“作业管理”两个页内标签。
- 接入 `GET/POST /api/teacher/teaching-records`。
- 接入 `POST /api/teacher/students/:studentId/growth-records`。
- 支持选择班级、学生、家长是否可见，并展示历史记录。
- 保留并优化现有作业发布、提交列表和批改功能。

验收：

- 教师可新建一条教学记录，刷新后仍存在。
- 教师可给本班学生发布成长反馈，家长端按可见性正确展示。
- 教学记录和作业管理切换时不丢失未提交的表单内容。

### UI-03 教师流程页完善

状态：已完成，并通过微信开发者工具人工验收。

范围：

- 增加全局完成率、班级进度和当前环节提示。
- 按时间段和流程环节分组展示步骤。
- 需要照片的步骤接入选择图片、上传和预览。
- 打卡成功后局部更新并显示时间，失败时允许重试。
- 已打卡步骤明确禁用，避免重复提交。

验收：

- 教师可以一眼看到每个班级和全局完成进度。
- 需要照片的步骤未上传凭证时不能误判为完成。
- 退出并重新进入后进度与打卡状态保持一致。

### UI-04 家长成长、作业与我的页面完善

状态：已完成，并通过微信开发者工具人工验收。

范围：

- 成长页支持多孩子切换、类型筛选、时间分组和出勤摘要。
- 作业页支持状态筛选、截止时间提醒、图片大图预览和批改结果突出显示。
- “我的”页面接入 `/api/me` 和 `/api/parent/children`，展示家长资料、孩子绑定和班级信息。
- 对尚未提供修改接口的资料明确标记为只读，不放置无效保存按钮。

验收：

- 多孩子家庭切换后，成长和作业数据不会串用。
- 家长可以快速区分待提交、待批改、已批改和已逾期作业。
- “我的”页面不再是占位内容。

### UI-05 通知、消息与聊天体验完善

状态：已完成，并通过微信开发者工具人工验收。

范围：

- 家长端区分“通知任务”和“家校会话”的信息层级。
- 教师端工作台和家长端底部导航展示可靠的未读提示。
- 页面显示时自动刷新，聊天页保留手动刷新作为故障兜底。
- 优化消息时间、已读状态、输入框安全区和长消息换行。
- 评估并接入图片消息；如本批不实现，页面不显示图片发送入口。

验收：

- 新消息到达后重新进入页面即可看到正确未读数。
- 双方发送消息后输入内容清空，失败时保留原输入。
- 不同孩子、家长和老师之间的会话严格隔离。

### UI-06 教师备课功能

本批需要新增后端数据能力，不能只复刻原型静态卡片。

范围：

- 设计教案/备课数据模型和数据库迁移。
- 新增教师教案列表、创建、编辑、状态变更接口。
- 支持主题、班级、日期、时长、教学目标、教学内容和状态。
- 小程序实现本周/全部/草稿筛选、创建和编辑页面。

验收：

- 教师可创建、编辑并发布教案。
- 教案只能由本人或授权教师维护。
- 刷新和重新登录后数据保持一致。

### UI-07 教师教研功能

本批需要新增后端数据能力。

范围：

- 设计教研活动、类型、时间地点、参与人和状态数据。
- 新增教研活动列表、详情、创建、编辑和参与状态接口。
- 小程序支持研讨、听课评课、培训筛选和活动详情。

验收：

- 教研页面不再显示固定静态活动或占位提示。
- 教师能查看真实活动并完成允许的业务操作。
- 活动权限和班级/校区范围明确。

### UI-08 管理后台功能补齐

范围：

- 增加作业、教学记录、成长记录和出勤/流程查询。
- 增加备课、教研所需的基础配置或管理入口。
- 为列表补充筛选、分页、明确的空状态和操作反馈。
- 保留现有老师、班级、学生、家长绑定、流程模板和审计日志能力。

验收：

- 管理员可以定位老师、班级和学生的关键业务记录。
- 管理动作有权限校验和审计记录。
- 小程序出现业务问题时可通过管理后台排查。

### UI-09 全页面回归与真机适配

范围：

- 对照历史原型逐页检查信息架构、颜色、间距和交互。
- 覆盖 iPhone 常见尺寸、安卓常见尺寸、刘海屏和底部安全区。
- 检查中文、超长文本、空数据、弱网、重复点击和接口失败。
- 完成教师端、家长端全业务人工验收清单。

验收：

- 所有底部导航页面均为可用页面，不存在“规划中”占位文案。
- 核心操作无横向溢出、按钮遮挡和输入框悬空。
- `pnpm typecheck`、`pnpm build` 通过。
- 微信开发者工具和至少一台真机通过主链路验收。

## 5. 推荐执行顺序

```text
UI-01
  -> UI-02 -> UI-03
  -> UI-04 -> UI-05
  -> UI-06 -> UI-07 -> UI-08
  -> UI-09
  -> CP-23 微信登录生产闭环
  -> CP-24 自动验证脚本
  -> CP-25 测试环境部署
  -> CP-26 文件存储生产化
```

其中 UI-02 至 UI-05 优先利用现有 API 补齐正式页面；UI-06 至 UI-08 涉及新数据模型和接口，应分别作为独立提交，不与纯视觉重构混在同一个提交中。

## 6. 每批验证要求

基础验证：

```powershell
pnpm --filter @ruizhibo/teacher-miniapp typecheck
pnpm --filter @ruizhibo/parent-miniapp typecheck
pnpm --filter @ruizhibo/teacher-miniapp build
pnpm --filter @ruizhibo/parent-miniapp build
```

涉及后端或数据库时增加：

```powershell
pnpm --filter @ruizhibo/api typecheck
pnpm --filter @ruizhibo/api build
pnpm --filter @ruizhibo/api seed
```

人工验收至少覆盖：

1. 正常数据。
2. 空数据。
3. API 未启动或请求失败。
4. 重复点击和提交中状态。
5. 页面返回后自动刷新。
6. 不同老师、家长和孩子的数据隔离。
